一、这是什么

这是一套用文件系统运营 AI 员工组织的完整系统：你拥有一个由 AI 员工组成的公司——有总管、有团队、有工单看板、有工作记录、有规章制度——但这一切没有数据库、没有后端服务，全部由普通文件和目录构成。

📦 你看到的东西

一个目录树。公司是一个大文件夹，员工各自有文件夹，每个工单是一个子文件夹，看板是双击就能打开的网页。

🤖 谁在干活

AI Agent（如 Claude、WorkBuddy 等平台的智能体）扮演员工。它们的工作方式 = 读写这些文件：改工单文件就是推进任务，写日志文件就是留痕。

👤 你要做什么

只说想法。你对总管描述需求，总管负责澄清、拆单、派活、验收、汇报。你不需要懂任何文件怎么组织。

🔍 为什么可信

一切工作有留痕、可审计、可回滚。看板只是投影，删了能重建；数据永远在文件里，不会因为某个系统挂掉而丢失。

二、核心思想（8 条支柱）

原则一句话解释
📁 文件即真相工单、工作记录、组织架构……全部是文件。看板、报表只是「投影」——只读展示，永不写回，删了可重建。
🗂 实体即目录公司、团队、员工、项目、工单各占一个文件夹；归属关系用字段声明（引用制），不靠物理嵌套，支持多对多。
🧠 人设即文件员工 = 一个文件夹：AGENTS.md 是人设（角色/职责/行为规范），skills/ 是技能，workspace/ 是工作区，memory/ 是记忆。平台自动加载人设，员工「出生即上岗」。
📚 技能自解释技能是一篇自包含的操作手册（触发词+全流程+红线），引用一行路径即可生效，不存在「人肉培训」。
🔀 调度中枢总管只调度不代劳；用户也可以直接指挥任何员工（双入口），但两个入口汇入同一套文件契约，杜绝两本账。
✍️ 留痕即审计一切工作必须写 worklog（只增不删）；工单状态与工作日志交叉核验，「说做了」和「真做了」互相咬合。
🏭 组织可实例化公司 = 母版模板 + 建司流程。目录结构说明书是结构契约，create-company 技能一键实例化新公司。
↩️ 变更可逆任何结构改动先出清单过目、备份 .bak、再执行；扩展先占字段契约（空值不报错），未来扩展零成本。
💡 一个比喻：这套系统相当于把「一家公司的组织架构 + 工作流 + 制度」翻译成了 Agent 天然会用的语言——文件读写。Agent 不需要学习任何专有系统，看懂文件就会干活。

四、系统怎么运作

4.1 数据流水线（单向）

数据层（真相）              生成层（校验+投影）           展示层（只读渲染）
tasks/ + affairs/ + worklog → generate_tasks.py          → kanban.html（工单看板）
                            → generate_dashboard.py      → dashboard.html（公司驾驶舱）
                                                           T*/teamboard.html（团队看板）
                                                           E*/mydesk.html（个人工作台）

Agent 改文件 → 生成器 3 秒内重算 → 页面自动刷新。方向铁律：展示层永不写回数据层；数据损坏删投影重跑即可，真相无损。

4.2 一件事的生命周期

阶段发生什么
① 你提需求对总管说想法。总管用「需求澄清」技能一问一答把想法理清楚，产出 PRD 存档。
② 拆解派单总管判断怎么落位（开工单/开事务/只记账），按「谁干合适」拆分工单，建父单跟踪需求闭环。
③ 员工认领员工会话启动时自动发现名下工单：worklog 记「计划中」= 认领；动工才改「进行中」（看板能区分已接未动）。
④ 执行留痕员工按技能规程干活，产物交 deliverables/，过程记 worklog 与 messages，状态随推进更新。
⑤ 审核闭环完成后转 review，总管或用户验收；拆出的子单全完成，父单才能关闭——需求整体闭环。
⑥ 沉淀经验写 memory（对自己有用）或知识库 methods/（对他人有用），总管定期提炼成技能/制度。

4.3 四分流：任何工作都有家

活的形态去处为什么
干一次就好的小事直聊记账worklog 记一笔即可，不产单不立实体
有终点、可验收的任务工单 TSK有限单元：状态机+验收+闭环
多工单多角色、有交付终点项目 P父单管需求闭环，项目目录管资料
无终点、养资产、按节奏重复
（长期内容运营、文件维护）		常设事务 AFF持续存在的不是任务而是「被养的资产」；affair.md 声明责任人+节奏，逾期自动告警

分界口诀一句话：项目有终点，事务没终点。

五、机制一览（14 项）

机制解决什么怎么运作（概要）
🎫 工单系统任务怎么派、怎么追一个工单=一个目录；7 值状态机；改文件即上板
🧩 需求闭环（父单）一个需求拆 N 个单后没人管整体type=需求 的父单 + 子单 parent 字段；子单全 done 父单才能 done；看板显示进度 🧩 n/m
🔗 前置阻塞工单有先后依赖blocked_by 字段；上游全 done 才能开工；自查+看板黄条+总管巡检三重保障
🤝 自动认领员工怎么「接到」派给他的单推（总管派发即回执）+ 拉（启动自扫漏接）；高优先级漏接自动开工，中低补认领等指令
🧵 并发工位卡同一员工多会话并行打架一会话一卡（sessions/seat-*.md）；同工单只有持卡会话改状态；memory 走 inbox 分片收口合并
✍️ 工作留痕干没干活说不清worklog 三段式（计划中/进行中/已完成）只增不删；与工单双账交叉核验
🗄 年度归档worklog 数据量增长按自然年切到 worklog-archive/；生成器全量扫描，历史照常显示，mydesk 可筛「含归档」
🔁 常设事务长期运营/维护类工作没处放AFF 目录（affair.md+assets/）；cadence 声明节奏；生成器从 worklog 推导上次推进，脱期黄条
⚖️ 领地自治谁有权改什么员工管自己目录、lead 管团队、负责人管项目、总管独占公司公共区；唯一例外：公司级技能引用行不可摘
🚪 双入口直接指挥员工 vs 走总管入口自由、机制收敛：直派时员工号池取号建单、自填 owner 留「用户直派」痕；两个入口同一套账
🎯 需求澄清想法→可执行需求总管 demand-clarify 技能：一问一答→PRD 存档→拆单
🧠 记忆体系经验怎么沉淀复用memory/（私人五要素）＋知识库 methods/（公共候选）→总管提炼成技能/制度/资料
📐 结构防漂移目录乱掉没人知道目录结构说明书（契约）+ --check-structure 机械自检：缺目录/野目录都告警
🏭 建司复制这套体系怎么复制到新公司company-template 空骨架母版 + create-company 交互式问卷；000 号总管自带全套技能入职运转

六、从零开始使用

6.1 建一家新公司（10 分钟）

  1. 打开 Agent 会话，工作区指向 OPC/；
  2. 说「建一家新公司，叫 XXX」——触发 create-company 技能；
  3. 回答建司问卷（公司 ID 自动分配、业务域、要不要预装技能/初始团队）；
  4. Agent 复制母版 → 重建 junction → 跑三项自检 → 000 号总管入职向你报到；
  5. 之后所有搭建（团队/员工/项目）都由总管按 SOP 推进，你只管提需求。

6.2 日常使用（你只需要会三句话）

你说发生什么
「我有个想法：……」总管进入需求澄清模式，一问一答帮你理清 → 出 PRD → 问你要不要拆单执行
「这个事办一下 / 直接让 E0002 去……」总管拆单派发；或员工直接领命（自动留「用户直派」痕、需要时号池取号建单）
「现在公司什么情况？」总管汇报看板状态；你也可以自己双击 dashboard.html 看驾驶舱

深潜 A · 设计原则全文深潜模式

架构哲学

P1 文件系统即真相：领域事实只存在于文件系统，一切视图只是投影，投影只读可重建。
P2 单一真相：任何事实只允许一个权威出处（如员工→团队归属只在 roster.md），引用代替复制。
P3 高内聚低耦合：每个模块/文件/技能只干一件事，模块间只通过明确定义的接口协作。
P4 单向数据管道：数据源→生成层→展示层单向流动，展示层永不写回。
P5 实体即目录、引用制归属：归属用字段声明不靠嵌套，支持多对多、可迁移重组。

技能体系

P6 三层技能隔离：公司级（skills/，≥2 人需要）/团队级/私有（1 人用），实体只存一处。
P7 引用与身份分离：AGENTS.md 只写人设+一行技能索引；触发词命中才读全文（渐进式披露，省 token）。
P8 workflow 只描述多技能编排：简单任务不进。
P9 技能自解释自包含：拿到 SKILL.md 就会操作，不依赖人肉培训。
P10 规范文件层≠平台技能：区分「靠引用读取」与「平台自动触发」两种形态。

工程实践

P11 容错：跳过+告警，不降级上板；P12 原子写（临时文件+替换）；P13 零依赖可移植（双击即开）；P14 契约先行（字段占位空值不报错）；P15 数据格式纪律（日期 YYYY-MM-DD、数组单行 JSON）；P16 改必测测必清。

协作流程与红线

P17 先调研汇报再讨论再执行；P18 一问一答澄清、决策先行存档；P19 流程偏好可覆盖、正确性底线不可妥协；P20 领地划分（升级为「领地自治+跨领地经中枢」）；P21 根治根因不打补丁；P22 多轮自审、成果用户自验；P23 坦诚不确定性、严禁迎合改结论；P24 变更优先零风险可逆。

深潜 B · 数据契约（A 层字段权威定义）深潜模式

task.md（工单）

字段必填说明
id / title / status✓编号（TSK+五位）/ 标题 / 7 值状态机（backlog·in_progress·review·done·failed·paused·cancelled）
owner / project—负责人/所属项目（可空=待派）
priority / type / due—高中低 / 需求·bug·任务·父单用「需求」/ 截止日
handoffs—流转链（单行 JSON 数组）：换负责人=改 owner+追加一条；铁律「最后一条 to=当前 owner，换人不换状态」
inputs—输入物引用（引用不复制）；上一手交付物=下一手输入物
completed_atdone 时✓实际完成时间（按期/逾期判断）
parent子单✓父单编号；子单全 done 父单才能 done
blocked_by—前置阻塞数组（单行）；所列全 done 才可开工；生成器三重校验
status_history—状态切换轨迹（可选审计）

worklog 条目（员工工作留痕）

字段说明
widW-YYYYMMDD-序号（自带日期，跨档唯一）
status计划中→进行中→已完成（三段式）
type工单 / 直聊 / 事务 / 自由
ticket / afftype=工单 填 ticket；type=事务 填 aff；大活工单可同时带两者
deliverable交付物相对路径（可选）

affair.md（常设事务）

字段说明
id / title / statusAFF+四位 / 标题 / active·paused·closed
owner / cadence养护责任人 / 节奏（每日·每周·每两周·每月·按需）
逾期推导生成器扫全公司 worklog 的 aff 字段取「上次推进」，超阈值（每日2天/每周9天/双周17天/每月35天）黄条；从未记账标「从未推进」——节奏数据是推导出来的，不是填出来的

roster.md（花名册，唯一权威）

列序：员工 ID｜路径｜岗位｜状态｜团队（多值逗号分隔）｜角色（lead=团队负责人）｜备注。另预留需求分析师岗位升级线。

task-index.md（编号台账）

TSK/AFF 分配记录 + 预留号池（约 20 个连续号，供入口 B 自助取号；先占台账后建单防撞号；水位 <5 总管补号）。

深潜 C · 扩展法则（总管落位决策树）深潜模式

总管接到任何构想，第一判断是「这属于哪类」，然后按固定流程落位：

构想
├─ 新实体（人/团队/项目多了）  → 新目录 + 实体卡 + 登记（roster/台账/parent 挂接）
├─ 教 Agent 怎么干            → 技能：定层（1人私有 / ≥2人公司级 / 团队内）
├─ 必须遵守什么               → 制度：声明要点+范围+红线，引用技能为执行标准
├─ 无终点养资产               → 常设事务 AFF（affairs/）
├─ 要多记一样数据             → A 字段契约 → B 生成器解析 → C 看板展示（三步铁律）
└─ 新报表/页面               → page-templates 复制，只读投影

技能定制三档（防止复制漂移）

① 纯引用（公司版适用）→ ② 增量扩展（"加上我的"：私有技能只写差异）→ ③ 真分叉（"换成我的"：改名新建+登记 fork，不再自动跟进）。禁止复制整份再微调——那会产生两份都像权威的复制品。

制度 vs 技能判定口诀

技能=能力（做了更好，触发词命中才加载）；制度=义务（必须/禁止/时限/追责，常在约束，审计锚点，修订须注明原因日期）。含"必须"语义的→建制度；纯流程→只建技能；纪律+新操作→成对建。

落位执行五步

① 归类（决策树）→ ② 出改动清单给用户过目 → ③ 备份 .bak → ④ 执行+同步目录结构说明书 → ⑤ 跑 --check-structure 与 --selftest 验证，汇报与回滚方式。

深潜 D · 双入口与领地自治深潜模式

原则：入口自由，机制收敛

用户→总管（入口 A，常态）或用户→直接指挥员工（入口 B，直通）：入口只决定活从哪进来，机制必须汇入同一套文件契约。每条机制设计时都要回答「入口 B 走到这步时谁触发、谁有权、留痕到哪」。

直派要建单员工号池自助取号：重读台账→占号→立即登记→建单（防并发撞号）
