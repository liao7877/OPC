# 工单操作规范（公司级）

> **适用范围**：全体员工（E0000 总管 / 后续按 `templates/employee-template/` 新增的员工）。
> **生效日期**：2026-08-27
> **制度性质**：本规范为制度声明（"必须怎么做"）；具体操作方法见公司级技能 `skills/ticket-system/SKILL.md`（"具体怎么操作"，含全流程示例/告警对照/红线），**本规范不重复技能内容，只引用为权威执行标准**。

---

## 一、制度要点（红线级，违反即不合规）

1. **唯一工单区**：所有工单统一存于 `workbench/tasks/TSKxxx-标题/`，一个工单 = 一个目录。
2. **编号纪律**：TSK 编号全局唯一，由总管 E0000 分配并登记（台账 `workbench/task-index.md`），员工不得自造编号。
3. **状态机**：仅允许 7 值——`backlog(待领) / in_progress(进行中) / review(待审) / done(完成) / failed(失败) / paused(暂停) / cancelled(取消)`；非法状态由生成器跳过并告警。
4. **流转铁律**：换负责人 = 改 `owner` + 追加一条 `handoffs`（单行 JSON）；最后一条 `handoffs.to` 必须等于当前 `owner`；**换人不改状态**。
5. **输入物**：引用不复制（`inputs: [{name, path}]`，路径相对 workbench/）；上一手交付物即下一手输入物。
6. **完成必填**：`status: done` 时必须填 `completed_at`（实际完成时间），用于按期/逾期判断。
7. **红线**：不修改看板/生成器文件（`workbench/kanban.html`、OPC 根 `opc_tickets.py`/`opc_dashboards.py`、`KANBAN_*`）；不删除 messages.md 历史；不自造编号。

## 二、执行标准（引用）

- **操作流程权威**：公司级技能 `opc://company:<本司ID>/skill/ticket-system`（新建/推进/流转/输入物/完成/告警对照/红线/全流程示例，自解释自包含）。
- 员工 AGENTS.md 已含技能引用行，按技能执行即可，无需额外培训。
