# AFFxxxx 常设事务契约（数据层 Schema，权威定义）

> **定位**：装"无终点、持续养护资产"的工作（决策 #17，2026-08-28）。与四分流的边界：
> 干一次就好→直聊记账；有终点可验收→工单；多工单有交付终点→项目；**无终点养资产按节奏重复→事务**。
> **管道不变**（P4）：affairs/ 是数据层，看板条带是投影；生成器只读不写回。

## 目录结构

```
workbench/affairs/AFFxxxx-标题/
├── affair.md     # 契约（frontmatter）+ 例行说明正文（这个活怎么干、标准是什么）
├── assets/       # 被维护的资产（文件/产出物，责任人领地）
└── logs/         # 过程留痕（可选）
```

## affair.md frontmatter（单行 key:value，同 task.md 家规）

| 字段 | 必填 | 说明 |
|---|---|---|
| id | 是 | AFFxxxx（四位序号，全局唯一；由总管分配并登记 task-index.md） |
| title | 是 | 事务标题 |
| status | 是 | `active(运行中) / paused(暂停) / closed(关闭)` 三值 |
| owner | 是 | 责任员工 ID（养护责任人，通常一人） |
| cadence | 是 | 节奏：`每日 / 每周 / 每两周 / 每月 / 按需` |
| priority | 否 | 高/中/低（缺省 中） |
| team | 否 | 归属团队（引用制） |
| created / updated | 是 | 日期 YYYY-MM-DD |
| note | 否 | 一句话备注 |

## 例行说明（正文）

写清楚：这个活具体干什么、质量标准是什么、干完放 assets/ 哪里、给谁看。**自解释自包含**（P9），责任人换了也能照着干。

## 记账与追踪协议

1. **日常干活**：责任人在自己 worklog 记 `type: 事务` + `aff: AFFxxxx`（三段式同工单条目：计划中→进行中→已完成）；
2. **大活**（需验收/多步追踪）：照常建工单 TSK（总管编号），worklog 条目 `type: 工单` 填 ticket，同时 `aff` 字段带上事务号（生成器据此关联到事务条带）；
3. **资产**：产出物放 `assets/`；也可引用外部路径（正文写明）。

## cadence 逾期判定（生成器推导，非人工填报）

- 生成器扫全公司 worklog（含归档），找 `aff=AFFxxxx` 的条目，取最新 `updated` 作为"上次推进"；
- 阈值：每日→2 天、每周→9 天、每两周→17 天、每月→35 天、按需→不判定；
- 超阈值且 status=active → 看板事务条带黄条"该跑没跑"，总管巡检处理；
- **查无任何记账记录** → 黄条"从未推进"（建了事务没干活）。

## 生命周期

- **新建**：找总管分配 AFF 编号 → 建目录写 affair.md → 总管登记台账；
- **暂停**：status: paused（不参与逾期判定，黄条消除）；
- **关闭**：status: closed（使命结束，目录保留 = 历史资产与留痕仍在）；
- **责任人变更**：改 owner 字段，messages 不存在——变更记录写进正文尾部（追加式）。
