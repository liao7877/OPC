# 员工自记录机制（worklog 三段式）

> 公司级纪律：**你的每一件工作都必须在本目录 `workspace/worklog.md` 留痕**。
> 这是公司看板统计你负荷、生成周报、公司驾驶舱动态流的唯一数据源。不记 = 白干（看板看不见）。

## 一、铁律（三条）

1. **三段式推进**：接到任务 → 写一条 `status: 计划中`；开始动手 → 改 `进行中`；干完 → 改 `已完成` 并挂交付物。
2. **只增不删**：条目一旦写入不允许删除，只能更新 `status` / `updated` / `note`（累计统计依赖完整历史）。
3. **双账一致**：工单活在 `task.md` 的状态与你在 worklog 的 status 必须同步推进；生成器会交叉核验并在看板上告警不一致。

## 二、怎么记（格式模板）

在 `workspace/worklog.md` 追加一块（多条记录 = 多个 `---` 块，依次向下追加）：

```
---
wid: W-YYYYMMDD-序号        ← 当天唯一即可，如 W-20260827-01
date: 2026-08-27           ← 接到任务的日期
title: 一句话说清做了什么   ← 必填，动词开头
status: 计划中              ← 计划中 / 进行中 / 已完成（三选一）
type: 工单                  ← 工单 / 直聊 / 事务 / 自由
ticket: TSK00012            ← type=工单 时必填且不可写其他值；直聊活不要填
aff: AFF0001                ← type=事务 时必填；工单若属于某常设事务的大活也可带
project: P0004              ← 关联项目代号（可选）
deliverable: 相对路径        ← 可选：以本员工目录根为基准，如 ../../../companies/C001/P0004-xxx/报告.md
updated: 2026-08-27         ← 每次动这条记录时更新为当天
note: 备注一句话             ← 可选
---
```

> **常设事务**（AFF，无终点养资产的工作，如长期内容运营）：接到事务的活 → 建条目 `type: 事务` + 填 `aff`；每次推进都记一笔——生成器据 worklog 推导事务节奏，**不记 = 事务被判脱期**。事务契约见 `opc://company:C001/workbench/affairs/AFF-SCHEMA.md`。

## 三、执行时机（Agent 行为规范）

| 场景 | 动作 |
|---|---|
| 从 task-index 台账/派单接到工单 | 立即建「计划中」条目 + 填 ticket |
| 用户直聊交代小事 | 建条目，type=直聊，不填 ticket |
| 接到常设事务的活（运营/维护类） | 建条目 `type=事务` + 填 aff=AFFxxxx；每次推进更新该条目 |
| 开始执行任务 | 该条目改「进行中」+ 更新 updated |
| 任务完成 | 改「已完成」；若产出了文件 → 挂 deliverable；若是工单 → 同步把 task.md 状态改为 done/cancelled 等 |
| 交接给他人 | 本条目保持现状，由接手人新建条目继续（流转历史在看板 handoffs 里呈现） |

## 四、反例（会被看板告警的写法）

- ❌ type=工单 但没填 ticket → 核验告警
- ❌ 干完活了把 worklog 条目改成已完成，但忘了关 task.md 的工单 → 「仍未关单」告警
- ❌ 名下工单 in_progress 但 worklog 里没有对应条目 → 「双账缺失」告警
- ❌ 删除旧条目"清理文件" → 违反只增不删，历史统计倒退

## 五、并发追加协议（同目录多会话并行时必守）

同一员工目录可能并发开多个会话（见公司级技能 `opc://company:C001/skill/concurrent-work`），追加 worklog 必须：

1. **重读**：追加前重新读一遍 worklog.md 全文（拿到最新内容）；
2. **补块**：在最新内容末尾拼上新块；
3. **原子写**：整内容写临时文件（worklog.md.tmp）→ 替换（保存为 worklog.md），不直接对旧文件盲追加；
4. **自读校验**：写完重读一遍，确认新块完整、旧内容无损；发现坏块立即按正确内容补写（只增不删，可自愈）。

## 六、归档机制（按自然年切档）

**契约**：`workspace/worklog.md` 只存当年热数据 + 上年未完成条目；往年已完成条目整块存 `workspace/worklog-archive/worklog-<年份>.md`（只增不改）。归档文件永久保留，不做二次归档。

**触发**：每年首次写 worklog 时，先执行切档：
1. 读热文件，把**上一年度的已完成条目**整块剪切到 `worklog-archive/worklog-<去年年份>.md`；
2. 上年**未完成条目**（计划中/进行中）留在热文件继续跟踪；
3. 热文件顶部留一行归档指针：`<!-- 2025 年度已完成条目已归档至 worklog-archive/worklog-2025.md -->`；
4. `wid: W-YYYYMMDD-序号` 自带日期，天然跨档唯一，归档不改号。

**看板可见性**：生成器扫描范围 = 热文件 + `worklog-archive/*.md` 全量——归档只是换了文件位置，历史记录在个人台/驾驶舱照常显示（个人台有"含归档"筛选开关）。**归档动作只动文件位置，不动数据本身**；生成器永不写回数据层。

**执行者**：员工本人（本节即规程）；总管巡检兜底（发现上一年度条目还躺在热文件会提醒）。

## 七、知识沉淀出口（可选字段）

某条经验对公司其他人也有用时，别只留在 worklog——提炼后交 `../../../companies/C001/公司知识库/methods/`（候选方法论），由总管评审提炼成技能/制度/背景资料（见知识库 KB.md）。个人下次干活的私有经验才进 `memory/MEMORY.md`。
