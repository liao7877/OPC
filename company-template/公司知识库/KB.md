# 公司知识库总纲（KB）

> **定位**：对公司/他人有用的显性知识库。**三分职能，一套目录**（MECHANISM_PLAN 决策 #13，2026-08-28）。
> **维护**：总管（领地：公司公共区）；员工可提交 methods/ 候选条目（提交即留痕，不改他人条目）。

## 一、三分边界（落位判定）

| 内容性质 | 去处 | 说明 |
|---|---|---|
| 教 Agent 怎么干（可执行流程） | 公司级技能 `skills/` | 技能管"怎么干"，不放这里 |
| 必须干什么（约束/红线/追责） | 规章制度 `公司规章制度/` | 制度管"必须干"，不放这里 |
| 给人/Agent 查的背景资料（行业/调研/案例） | `common/` | 只供查阅，不指挥行为 |
| 员工经验，对公司别人也有用 | `methods/`（候选中转区） | 等总管提炼，见 §三 |
| 员工经验，只对自己下次有用 | 员工 `memory/MEMORY.md` | 私人记忆，不进知识库 |
| 项目过程知识（调研/方案对比/评审） | 各项目 `P00xx/knowledge/` | 项目领地自治；跨项目复用价值由总管提炼观点进 common/（不复制文件） |

## 二、目录结构与命名

```
公司知识库/
├── KB.md              # 本文件（总纲）
├── common/            # 背景资料库：行业资讯/通用调研/踩坑案例
│   └── <主题>.md
└── methods/           # 候选方法论（中转区）：员工经验提交处
    └── <日期>-<员工ID>-<主题>.md
```

- common/ 条目：一主题一文件，文件头注明来源与日期；
- methods/ 条目命名：`YYYY-MM-DD-E00xx-主题.md`，正文五要素（场景/解法/适用前提/反例/验证，与 memory 五要素同构）。

## 三、经验→方法论提炼流（methods/ 生命周期）

1. **提交**：员工把对公司有用的经验写成 methods/ 条目（worklog-discipline §七 的出口）；
2. **评审**：总管巡检时顺带评审新条目（AGENTS.md 启动流程第 5 步）；
3. **三选一出路**：
   - 操作类（别人可照做的流程）→ 提炼成公司级/私有**技能**；
   - 约束类（"以后必须这样"）→ 提炼成**规章制度**（引用技能为执行标准）；
   - 背景类（查证用资料）→ 转正进 `common/`；
4. **归档**：已提炼或重复过时的条目，文件头加 `status: 已提炼(去处: xx)` 标记，不删（留痕）。

## 四、红线

1. 技能/制度的内容不复制进知识库（引用代替复制，P2）；
2. methods/ 条目只有提交者和总管能动；
3. common/ 收录前总管过目（防垃圾入库）；
4. 项目知识不复制进 common/（提炼观点，不搬文件）。
