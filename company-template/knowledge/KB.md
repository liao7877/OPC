# 公司级知识库（KB）

> **定位**：三级知识库的公司级——员工级 `E00xx/knowledge/` → 团队级 `T00x/knowledge/` → **公司级 `knowledge/`**（总管管、全员可读）。
> **维护**：总管独占；员工/团队的知识经**上浮**或**登记**进入（§三），不改他人条目。
> **依据**：MECHANISM_PLAN §十七（决策 #19）；原则见 PRINCIPLES P33。
> **模板说明**：本文件随 `create-company` 复制到新公司，`<本司ID>` 占位在建司时替换。

## 一、组织原则

- **目录 = 主题分类**（`common/` 背景资料、`methods/` 方法论…），**成熟度一律看 frontmatter `status` 字段，不靠目录名**（P33 ④）。
- **每级同构**：`KB.md`（本文件，人写）+ `glossary.md`（受控词表）+ `INDEX.md`（生成物，勿手改）+ 主题子目录。同构让 agent 检索逻辑只写一份，上浮时零格式转换。
- **三级加载**：索引行（常驻）→ `summary`（命中才读）→ 全文（确认有用才读）。**`summary` 必填**——不填则加载机制失效。
- **真实路径**：`companies/<本司ID>/knowledge/`（稳定锚，浏览器/编辑器可直开）；文档引用一律 `opc://company:<本司ID>/knowledge/...`（符号层，resolver 可校验）。

## 二、条目字段契约

| 字段 | 谁填 | 说明 |
|---|---|---|
| `title` `type` `tags` | 人 | 索引行可见部分，**决定检索命中率** |
| `summary` | 人 | 2-3 句，摘要层加载内容 |
| `status` | 人 | 草稿 / 候选 / 正式 / 待复核 / 已归档 / 已废弃 |
| `author` `maintainer` | 人+审批 | 作者署名答疑、维护人管格式复核（**分离**：解「没人懂细节」+「没人管腐烂」） |
| `review_by` | 人 | 复审到期日（巡检 #14 提醒） |
| `derived_from` `supersedes` `source` | 人 | COW 衍生链 / 取代关系 / 登记型条目原文指针 |
| `hits` `tokens` | **机器** | 命中热度（LRU）+ 全文体积估算（agent 据此判断值不值得读全文） |

`type` 取 diátaxis 四分法：`method`（怎么干）/ `reference`（查什么）/ `case`（案例与解释）/ `glossary`（术语）。

## 三、两条入口通道

| 通道 | 适用 | 谁批 | 动作 |
|---|---|---|---|
| **上浮** | 内部知识：脱离原作者仍成立 + 跨 N≥2 个角色有用 | 总管审批 | 物理搬家 + 原处留**真实 `.md` 存根** |
| **登记** | 外部资料 / 长报告：只要结论，全文太重 | 收录即可、总管过目防垃圾 | `source` 指原文，正文只写结论 |

**不满足上浮准入的挡回原层**——不是「换个方式上浮」，是「不该上浮」。存根必须是真实文件而非索引里的一行，否则原路径的 `opc://` 引用全部断链。

## 四、三档可覆盖性

| 类型 | 能否覆盖 | 机制 |
|---|---|---|
| 制度 / 红线 | ❌ | 只能申请改源头，下级只读 |
| 方法论 / SOP | ⚠️ 可衍生不可覆盖 | COW 复制到本地做变体，强制标 `derived_from`，**源不变** |
| 背景资料 / 事实 | ✅ 可补充可纠错 | 本地标 `source`/`supersedes`，同时发纠错工单 |

## 五、红线

1. **永不自动删除**——只降级与归档，淘汰由人工裁决（P33 ③）；
2. 技能与制度的内容不复制进知识库（引用代替复制，P2）；
3. 上浮必须搬家 + 留真实存根，**不复制**（P33 ②）；
4. 状态写字段，不建 `草稿/` `已归档/` 之类的目录（P33 ④）；
5. 术语走 `glossary.md` 归一，禁止同义分裂（工单 / 任务 / ticket 只留一个）。

## 条目模板（登记新条目时复制此骨架填空——frontmatter 是机器可读面，人填完即进索引）

```markdown
---
title: 条目标题（检索命中的关键，写用户会搜的词）
type: method        # method=怎么干 / reference=查什么 / case=案例与解释 / glossary=术语
tags: [标签1, 标签2] # 术语与同义词归一见 glossary.md；禁用词不进 tag
summary: |
  2-3 句摘要：这条知识解决什么问题、何时用、结论是什么——不填则三级加载失效
status: 正式         # 草稿/候选/正式/待复核/已归档/已废弃（状态进字段不进目录名，P33）
author: E000x        # 作者（内容答疑找谁）
maintainer: E000x    # 维护人（格式复核，与 author 分离：解决搬家后无人懂细节）
review_by: 2026-12-31 # 复审到期日（TTL，到期巡检 #14 提醒）
source: ""           # 外部资料的原文指针（登记型条目必填，正文只写结论）
derived_from: ""     # 衍生自上级哪条（COW 变体必填，源不变）
supersedes: ""       # 取代哪条旧条目
---

正文：按 type 定位写——method 写步骤、reference 写事实、case 写背景与结果。
```

> `hits`（命中热度）/ `tokens`（体积估算）由机器维护，人勿填。

## 结构权属（默认冻结，2026-08-30）

- 本层目录结构默认视为**用户设计**：冻结——任何人（含本人/总管）不得增删改名/移动/重分类；需要调整 → escalate 向用户汇报「动什么/为什么/建议」，拍板后执行
- **授权自治登记处**：用户明示「此目录归你自治」→ 在此登记：`<子目录> → 授权 <E000x> 自治（日期）`；无登记 = 冻结
- 内容层不受限：条目登记/提炼/补 frontmatter 自由（按上方条目模板）
