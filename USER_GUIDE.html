OPC 用户手册

写给「完全不了解系统内部」的你：只需要会三件事——把总管目录当工作区打开、用大白话说需求、等验收。剩下的（拆单、派活、记录、巡检、告警）是总管和机制层的事。

① 30 秒上手

唯一的日常入口：用你的 AI Agent 工具（WorkBuddy / Claude Code / Codex…）把 companies/C001/E0000/ 目录当工作区打开一个会话——总管会自动加载身份、职责和技能。然后像跟真人经理说话一样派活即可。
这几天帮我把公众号内容流程理一下，先给我个方案。

总管会自己澄清需求 → 拆成工单 → 派给员工 → 跟踪进度 → 完成后向你汇报验收。你全程不需要知道「工单存在哪个目录」这种事。

② 怎么派活（两种入口，殊途同归）

入口 A（推荐常态）：找总管

1
说构想——不用结构化，一句话即可。模糊没关系，总管会一问一答澄清（一次只问一个问题）。
2
等方案确认——总管先调研汇报、给方案，你拍板后才会动手（先存档再执行）。
3
等验收——干完后总管/员工提交成果，你是最终验收人；不满意直接说哪里不行，会返工。

入口 B（直通）：直接指挥某个员工

你也可以把某个员工目录（如 E0001/）当工作区打开，直接派活。机制上完全支持：员工会自取工单号、自建台账、留痕「用户直派」。

规则差异：涉及公共领地的事（改公司制度、加员工、动看板机制），员工会按「领地自治」转报总管——这不是怠工，是防止越权改坏公共部分。

无论哪个入口，都请给三样东西（缺了会被追问）：① 清晰的目标（做成什么样算完）② 验收标准（你打算怎么判断合格）③ 时限（什么时候要）。这就是工单里的 title / 验收 / due，你给得越清楚，返工越少。

③ 怎么和员工对话

和员工会话（或总管转述）时，把员工当成「能力很强但每次醒来失忆的新同事」——他的长期记忆在文件里，当次会话的上下文需要你说清楚：

派活时说清楚

  • ◇ 做什么、为什么（背景一句即可，详细资料给路径）
  • ◇ 交付物是什么形态（报告？代码？一篇文案？）
  • ◇ 验收标准 + 时限
  • ◇ 相关资料的文件路径（员工会自己去读）
把上周的行业调研（资料在 项目P0001/knowledge/ 下）整理成一页决策建议，重点是三点结论，今天下班前给我。

过程与收尾

  • ◇ 员工会先认领工单（worklog 建账）再动工，这是纪律，不用你催
  • ◇ 遇到阻塞/需求不明，员工会在工单里发升级信箱，总管心跳会发现并弹系统通知找你——那是唯一会打扰你的事
  • ◇ 完成后你看成果、表态：满意 → 说「验收通过」，工单关单；不满意 → 说具体哪里不行，走返工
  • ◇ 对话产生的结论会自动留痕（worklog / 工单 messages），下次换会话不丢

④ 你要做的 / 不用做的

✅ 你要做的（很少）

  • ◇ 派活：跟总管说话
  • ◇ 验收：看成果、说通过或不通过
  • ◇ 回应急：系统通知弹出「[高优] 升级」时，找总管处理
  • ◇ 首一次性配置：换机器/新 clone 时跑一次初始化命令（见 §6）

❌ 你不用做的

  • ◇ 不用记任何目录结构、编号规则（C/T/E/P/TSK 是给 Agent 用的）
  • ◇ 不用手动改看板/报表（它们是自动生成的投影，改了也会被重生成覆盖）
  • ◇ 不用记得「谁该干什么」——看板、巡检、双账核验替你盯
  • ◇ 不用担心改名/搬家弄坏引用——命名空间机制自愈，跑一次 --ensure-links 即可
  • ◇ 不用维护技能索引、花名册、台账——总管与机制层负责

⑤ 机制地图（系统怎么自己转）

了解这些不必须，但知道有什么，你就知道「哪些话可以直接对总管说」。

🎫 工单系统（双车道）

要验收的活才建 TSK 工单（有人检验成果/要交接/跨会话/多人协作）；干完就完的小活走直聊——员工在 worklog 记一笔留痕，不用建单，你随便聊。工单的：标题/负责人/验收/截止/阻塞关系（blocked_by）/父子单。七个状态：backlog → in_progress → review → done，另有 failed / paused / cancelled。写错状态会红牌上板而不是消失。

📋 三级看板

公司驾驶舱 dashboard.html、团队 teamboard.html、个人桌面 mydesk.html、工单墙 kanban.html。全部由真相自动生成——看板即进度，你随时打开浏览器看。

📝 worklog 双账

员工干任何活都自记录（三段式：计划中→进行中→已完成），与工单状态交叉核验：认领了没记录、干完了单没关，都会被点名告警。

💓 公司心跳

每 30 分钟自动巡检 10 项：阻塞该开工的、没人认领的、双账不一致的、脱期事务、升级信箱（critical 唯一会打扰你）、号池水位、知识库增量、僵尸工位卡、看板数据陈旧等。异常 → 写日志 + 弹系统通知 → 生成待办快照给总管处置。

🃏 工位卡与并发

一个会话=一张工位卡。多会话各干各单；共干一单时只有持卡会话有权改状态。机制层写路径全部有锁，并发追加用 --append 命令——多开会话是安全的。

🧠 技能体系

员工会什么=读了哪些技能（三层：公司级/团队级/私有）。每个技能自带触发词与全流程，命中才加载。总管新增能力=建一个技能文件，索引自动更新。

📚 知识库三分

查资料 → 公司知识库/common/；员工经验 → methods/（总管提炼成技能/制度）；项目资料 → 各项目 knowledge/。心跳会自动发现新知识并提醒总管评审。

🚦 编号与台账

一切实体有编号：公司 C/团队 T/员工 E/项目 P/工单 TSK/事务 AFF。台账 task-index.md 记录分配与预留号池，取号原子化防撞号。

🏢 开新公司

对组织根会话说「建公司」即可：按模板一键拉起，总管自动入职。模板与实例的机制同步由 --diff-template 盯着，不会悄悄漂移。

⑥ 命令速查（99% 情况你只需要前两条）

# —— 新电脑 / 新 clone（一条命令全搞定，含心跳定时任务）——
python opc_resolver.py --bootstrap       # 一键自举：链接+钩子+看板数据+技能索引+每日心跳
python opc_resolver.py --doctor          # 终检五项，全绿 = 可以正常使用（自带自愈）
run_boards.bat once                      # 可选：手动重建看板（bootstrap 已自动做过；macOS/Linux: ./run_boards.sh once）

# —— 心跳管理（默认每 30 分钟，异常弹系统通知；通知只报新发现不轰炸）——
python opc_patrol.py --register-heartbeat --company C001 --every 30   # 手动挂（bootstrap 已自动挂）
python opc_patrol.py --unregister-heartbeat --company C001            # 撤销

# —— 总管/员工日常用（你不用记）——
python opc_tickets.py --company C001 --new --auto-id 标题 --owner E0001   # 原子取号建单+占台账
python opc_tickets.py --company C001                                     # 重算工单看板
python opc_dashboards.py --company C001 --verify                         # 三级看板+一致性校验
python opc_patrol.py --company C001                                      # 手动巡检一次
python opc_model.py --append worklog路径 块文件                           # 锁内追加（并发安全）
python opc_model.py --sync-index                                         # 重生成技能索引
python opc_resolver.py --diff-template                                   # 实例↔模板 漂移检查

⑦ 常见情况怎么办

情况怎么办
看板上有红牌工单它的 status 写了非法值（坏数据会上板不隐藏）。跟总管说「把 XX 工单状态修正一下」即可。
弹了系统通知「[高优] 升级」有员工在工单里举手求助（critical，唯一会打扰你的项）。开总管会话说「处理一下巡检待办」，总管会按 patrol-pending.md 逐项处置。
换了电脑 / 重新 clone 了仓库跑 python opc_resolver.py --bootstrap 一条命令即可——链接、钩子、看板数据、技能索引、心跳定时任务全部自动重建并终检。
想改公司/员工/项目目录名随便改。改完在 OPC 根跑一次 python opc_resolver.py --ensure-links，所有引用自愈。
觉得某个员工能力不对/缺技能对总管说「给 E0001 加一个 XX 技能」——总管按落位 SOP 建技能、更新索引，你不用碰文件。
同一个活想多人/多会话并行直接开多个会话。工位卡 + 锁保证不互相覆盖；谁持卡谁有权改单子状态。
怀疑员工没干活/账不对打开公司驾驶舱 dashboard.html 看风险区；或者直接问总管「最近有什么双账不一致/未认领的」——巡检清单里都有。
想直接抢活干（绕过总管）可以（入口 B），但公共领地的事员工会转总管。车道判定：要验收的活建工单，干完就完的小活直聊留痕即可（问答/随手小改不用建单）；拿不准就建单。
