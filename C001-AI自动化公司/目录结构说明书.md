# C001 目录结构说明书（结构契约）

> **定位**：公司目录下每个目录/文件"**是什么真相的载体、谁维护、红线是什么**"的唯一权威声明。
> **用法**：①总管落位任何新东西前对照本表（动态流程见 `E0000-AI员工-总管/skills/mechanism-sop/SKILL.md`）；②结构变更必须同步更新本表；③`python ../../../opc_tickets.py --company C001 --check-structure` 按 §一 做机械自检。
> **层级**：`opc://org`（组织层，OPC 根）→ 本公司 `opc://company:C001` → 实体目录 → 实体内部。组织层说明见 `opc://org/principles` 与 `opc://org/agent-ecosystem`。

## 一、公司根一级结构（--check-structure 校验范围）

| 条目 | 类型 | 职责（真相载体） | 维护者 | 红线 |
|---|---|---|---|---|
| `company.md` | 文件 | 公司宪法：实体清单/命名规范/任务区约定 | 总管 | 实体清单与 roster/目录保持一致 |
| `AGENTS.md` / `CLAUDE.md` | 文件 | 平台自动加载入口（只指路 → company.md） | 总管 | 不装业务内容 |
| `workflow.md` | 文件 | **公司级工作流**：双入口/交接/升级路径/闭环协议 | 总管 | 跨团队协作不绕过总管 |
| `skills/` | 目录 | 公司级技能实体（怎么干的知识，唯一出处） | 总管 | 实体只存此处；不复制进下层 |
| `workbench/` | 目录 | 工作执行区：`tasks/` 工单真相 + `affairs/` 常设事务 + 生成器 + kanban 投影 + task-index 台账 | 总管管理，廖哥指挥专属 Agent 改生成器/看板 | 员工只动 tasks/ 与 affairs/ 自己名下的；看板永不写回 |
| `templates/` | 目录 | 员工母版 employee-template（新建员工唯一出处） | 总管 | 新建员工禁止退回老结构 |
| `../companies/C001/page-templates/` | 目录 | 三级看板页面母版 | 总管 | 升级只改模板一处 |
| `../companies/C001/公司规章制度/` | 目录 | 制度声明层（必须干；引用技能为执行标准） | 总管 | 不复制到团队/员工；操作细节进技能 |
| `../companies/C001/knowledge/` | 目录 | **公司级知识库**（决策 #19 三级同构：KB.md 人写 + INDEX.md 生成物 + 主题子目录） | 总管独占；员工/团队经**上浮**（搬家+存根）或**登记**（结论+指针）进入 | 技能/制度不复制进库；**不复制**（P33 ②）；永不自动删（P33 ③） |
| `E00xx/knowledge/`、`T00x/knowledge/` | 目录 | **员工级 / 团队级知识库**（同构） | 员工本人 / 团队 lead | 上级两层只读；定制走 COW + `derived_from` |
| `E0000-AI员工-总管/` 等 E* | 目录 | 员工实体（人设/技能/工作区/记忆） | 该员工 | 领地自治；公司级引用行不可摘 |
| `T001-AI开发团队/` 等 T* | 目录 | 团队实体（team.md/notices/skills/workflow） | 团队 lead | 成员清单不维护于此（roster 唯一权威） |
| `P0004-公司看板与工作记录系统/` 等 P* | 目录 | 项目实体（project.md 含 owner/workflow/knowledge/） | 项目负责人 | 任务不物理挂项目下 |
| `run_boards.bat` 等脚本 | 文件 | 运维（离线应急）：看板一次性重算 | 总管 | 日常由 OPC 服务实时托管，无需手动 |
| OPC 根 `opc_service.py` | 文件 | 公司自转的中枢（组织级，不在公司目录内）：看板实时化 + 巡检 13 项 + 通知 | 总管（bootstrap 自动挂） | 进程=宿主、公司=租户；自启项 `OPC-Service.vbs`（Windows）/ crontab `@reboot`（mac-Linux），删之即卸载 |
| `dashboard.html` / `*-data.js` | 文件 | 公司驾驶舱投影（只读） | 生成器产出 | 永不手工编辑 |

## 二、实体目录内部契约

### E00xx 员工目录
| 条目 | 职责 | 红线 |
|---|---|---|
| `AGENTS.md` | 人设唯一真相（角色/职责/启动三动作/引用行/领地规则） | 公司级技能引用行不可摘除（唯一例外需经总管） |
| `CLAUDE.md` | Claude Code 适配（一行 @AGENTS.md） | 不装内容 |
| `workflow.md` | 员工级工作流（多工单/多技能编排） | 技能引用不进此文件 |
| `skills/` | 私有技能实体（逻辑引用 `opc://company:C001/skill/<名称>`）+ INDEX.md 披露索引（先查索引命中才读全文） | 新增技能：实体 + INDEX 登记一行 |
| `.workbuddy/skills` | junction → 本目录 skills/（平台披露通道） | 删除即断披露，需重建 |
| `memory/MEMORY.md` | 长期记忆合并区（五要素） | 并发会话不直写（走 inbox/） |
| `memory/inbox/` | 并发会话沉淀分片，收口合并后删 | 分片不烂尾 |
| `workspace/worklog.md` | 工作留痕真相（三段式） | 只增不删；双账一致 |
| `workspace/worklog-archive/` | 往年已完成条目归档（worklog-<年>.md，按自然年切） | 只增不改；生成器全量扫描，历史照常显示 |
| `workspace/sessions/` | 工位卡（seat-*.md，一会话一卡） | 不删他人卡；收口翻"已收口" |
| `roster.md`（仅 E0000） | **全公司员工花名册唯一权威**：ID/路径/岗位/状态/团队/角色(lead) | 新员工必须登记；lead 在此声明 |

### T00x 团队目录
`team.md`（ID/名称/lead 声明，引用 roster）、`workflow.md`（团队级，lead 统筹）、`notices.md`（公告，---块追加）、`skills/`（团队级技能）。

### P00xx 项目目录
`project.md`（ID/名称/团队引用/**owner 项目负责人**）、`workflow.md`（项目流水线）、`knowledge/`（项目过程知识，负责人自治）。

### 工单目录 `workbench/tasks/TSKxxx-标题/`
`task.md`（frontmatter 契约：id/title/status/owner/project/priority/type/due/created/updated + 扩展 `parent`/`blocked_by`）、`messages.md`（追加式）、`deliverables/`、`logs/`。

### 常设事务目录 `workbench/affairs/AFFxxxx-标题/`（决策 #17）
`affair.md`（契约：id/title/status(active·paused·closed)/owner/cadence(每日·每周·每两周·每月·按需)/priority + 例行说明正文）、`assets/`（被养护的资产）、`logs/`。权威 Schema：`workbench/affairs/AFF-SCHEMA.md`。
- 与项目分界：**项目有终点，事务没终点**；
- 记账：员工 worklog 记 `type: 事务` + `aff: AFFxxxx`；大活照常开工单（条目同时带 aff）；
- 节奏保障：生成器按 worklog 推导"上次推进"，超 cadence 阈值（每周→9 天等）看板黄条；从不推进标"从未推进"。

## 三、机制字段契约（数据层 A 层）

| 字段 | 所在 | 语义 | 校验 |
|---|---|---|---|
| `blocked_by: [TSK..]` | task.md | 前置阻塞：所列全 done 才可开工 | 引用存在；未清开工告警；解锁提示 |
| `parent: TSKxxx` | task.md | 子单归属需求父单 | 父单存在；父单 done 需子单全 done |
| `aff: AFFxxxx` | worklog.md | 常设事务引用（type=事务必填；大活工单也可带） | 生成器推导事务节奏；超期告警 |
| `reserved-for-claim` 段 | workbench/task-index.md | 预留号池（入口 B 自助取号） | 取号先占台账（原子三步，ticket-system §1.55）；水位 <5 补号 |
| `patrol-log.md` | OPC 服务巡检产出（opc_patrol.py） | 巡检发现追加（只增不删） | 处置由总管完成 |
| `archive/` | 历史过程文档（KANBAN_* 等） | 只读存档 | 不作为现行机制依据 |
| `cadence` | affair.md | 事务推进节奏（每日/每周/每两周/每月/按需） | 超阈值黄条；按需不判定 |
| `worklog-archive/worklog-<年>.md` | 员工 workspace | 年度归档（冷数据） | 按自然年切；生成器全量扫描 |
| `seat-*.md` | 员工 workspace/sessions/ | 工位卡（并发会话声明） | 启动必建；收口必翻 |
| `角色` 列 | roster.md | lead=团队负责人 | 每团队至少一名 lead |
| `owner` | project.md | 项目负责人（项目领地自治人） | 缺失时项目无自治人（告警提示） |

## 四、投影层（只读，永不写回）

`dashboard.html + dashboard-data.js`（公司）· `T*/teamboard.*`（团队）· `E*/mydesk.*`（个人）· `workbench/kanban.html + tasks-data.js`（工单）。管道：`tasks/ + worklog → OPC根 opc_tickets.py + opc_dashboards.py → *-data.js → html 只读渲染`（机制代码不在公司目录，公司只留 run_boards 薄壳）。投影损坏删除后重跑生成器即可重建。

## 五、扩展落位速查（详见 mechanism-sop）

新实体→目录+登记；新操作知识→技能（三档：引用/增量扩展/真分叉）；新约束→制度（能力/义务口诀）；新数据事实→A字段→B解析→C展示；新视图→page-templates 复制。**本说明书随每次结构变更同步更新，`--check-structure` 兜底防漂移。**
