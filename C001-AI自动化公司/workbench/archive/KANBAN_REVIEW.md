## 〇、一句话结论

**核心诉求"改了自动上板、页面无感刷新"当前不成立。** `--watch` 只负责让"数据文件"保持最新，但已打开的页面与 Python 监听进程之间没有任何通信通道，浏览器也不会二次拉取已加载的 `<script>`，**因此必须手动刷新浏览器才能看到变化**。其余为一批确定性的功能 bug（详情链接 404、坏数据上板、筛选白屏）和 PRD 多处与实现背离。

## 一、头号问题（P0）：自动重跑 ≠ 页面自动刷新

**用户原问：自动重跑了，页面会自动同步刷新吗？**
**答：不会。必须手动刷新。**

### 根因（三层叠加）
1. `--watch` 是独立的 Python 进程，重跑后只重写了 `tasks-data.js / .json` 两个**磁盘文件**；
2. 浏览器 `kanban.html` 用 `<script src="tasks-data.js">` 在**页面加载时一次性**把数据读进 `window.KANBAN_DATA`，之后不再重读；
3. `file://` 协议下浏览器**禁止 `fetch` 本地文件**（CORS），也没有文件系统变更通知 API，所以页面既无法被动接收通知，也无法主动轮询文件 mtime。

→ 结果：数据文件是最新的，但页面仍停留在旧快照。我此前 final reply 里"改完 md，自动重跑+刷新后大家看到同一份"的"刷新后"表述有歧义，实为"手动刷新页面后"，与"自动"是两回事，这是沟通/文档缺陷，先认。

### 修复方向（二选一，需你拍板）
- **方案 X（推荐，保留 file:// 双击即开）**：在 `kanban.html` 内加前端轮询——每 N 秒（如 3s）动态插入一个带 cache-buster 的 `<script src="tasks-data.js?_=时间戳">`，重新赋值 `window.KANBAN_DATA`，比对 `generated_at` 变化则自动 `render()`。零后端、不破坏"A 静态生成"架构，改动集中在前端。
- **方案 Y（引入轻量本地服务）**：起 http server + SSE/WebSocket 推送，实时性最好，但偏离"双击即开、零依赖"，接近当初否掉的 B 方案。

### 11.1 过程中自抓一个 P1 bug（自己引入）
`runFrontendSelftest` 断言字符串含字面 `</script>` → 浏览器 HTML 解析时 script 元素被**提前终止**，整个看板 JS 崩溃。已修为 `<\/script>`（与生成器防御 `</script>` 注入同一套路）；验证脚本同步改用"排除 src 的 script 抽取正则"。教训：**前端 JS 字符串里永远不要写字面 `</script>`**。
