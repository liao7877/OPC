数据模型（task.md 权威 Schema）

YAML frontmatter · 单行 key: value · --- 包裹
字段类型必填用途 / 说明
idstring是全局唯一编号（TSKxxx，总管分配）
titlestring是卡片标题
statusenum是backlog / in_progress / review / done / failed / paused
ownerstring否当前负责人 ID（空则「未分配」）
owner_namestring否负责人可读名（目录未建时兜底，工单自包含）
project / project_namestring否所属项目 ID / 可读名（兜底）
priorityenum否高 / 中 / 低（卡片圆点+文字）
typeenum否需求 / bug / 任务
duedate否预估截止日
completed_atdate否实际完成时间（status=done 必填，否则告警）
tagslist否标签筛选
created / updateddate否创建 / 更新时间
handoffslist否流转链 [{from,to,at,reason}]，与状态解耦
status_historylist否状态变更时间线 [{to,at}]（详情「状态轨迹」）
inputslist否输入物引用 [{name,path}]，不复制文件
parent/children/links-否预留字段（未来并行协作 / 子任务拆分）
descriptiontext否正文描述

看板功能架构

C 层能力地图（全部由 A 层数据驱动）
🗂 分组视图
状态 / 项目 / 负责人 / 参与者（含历史经手人，一单可归多列）
🔍 筛选检索
优先级 / 类型 / 标签（多选）/ 关键词（含名称与参与者）
🎴 卡片
标题 + ID 标签 + 状态色条 + 负责人（名+号）+ 优先级（点+文字）+ 项目 + 截止日（逾期标红）+ 流转/输入标记
📄 详情面板
字段网格 + 流转轨迹时间轴 + 描述 + 交接备注 + 输入物（可点击）+ 交付物 + 执行日志
🔁 自动同步
文件变动 → 生成器重跑 → 前端 3 秒轮询比对 → 无感刷新
🎨 双主题
暗 / 亮切换（localStorage 记忆，**默认亮色**）
📊 统计与导出
顶部统计栏（各状态/逾期中）+「⬇ 导出 CSV」（Excel 中文不乱码）
⌨️ 快捷操作
↑↓ 键盘导航卡片、URL 参数分享视图（?groupBy=?tags=）、前端自测（?selftest=1）

容错与告警

坏数据不污染看板 · 警告不静默
跳过 + 告警 坏数据不上板
情形处理
task.md 无 --- 包裹跳过该工单
status 非法 / 缺失跳过，不降级 backlog
id 重复（两个同名 TSK）跳过后者，避免点开错单
告警不跳过 提示你修，工单照常上板
情形处理
handoffs 最后 to ≠ owner提示对齐
inputs 路径不存在详情标「⚠️ 路径失效」
done 未填 completed_at提示补填
日期格式无法识别提示改 YYYY-MM-DD
from == to 无意义流转提示检查

系统边界与扩展路径

插件化接入 · 按管道演进不推倒重来
🚧 边界铁律
  • Agent 只对接 A 层文件（tasks/），不知道看板怎么用
  • 看板（C 层）不对接 Agent，只读投影
  • 改看板 UI/逻辑 = 廖哥 + 前端 Agent 改 kanban.html / generate_tasks.py
  • 新增机制 = 先加字段/约定 → 再解析 → 再展示（数据层长出）
  • 看板永不写回文件（写回 = C 方案，需后端）
🧩 扩展路径（已留接口）
需求路径
看板写回 / 拖拽改状态C 方案，需后端，暂不做
并行协作 / 子任务parent/children/links 已预留
统计（按期率 / 平均时长）数据已含 completed_at / created / due
多角色视图 / 快捷 URL前端 ?owner=E0002 参数化
