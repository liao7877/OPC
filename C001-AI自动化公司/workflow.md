# 公司工作流（公司级 workflow）

> **定位**：三级工作流中的"公司级"——跨实体协作协议。规定需求怎么流入、员工/团队/项目之间怎么配合、卡住了怎么升级。
> **撰写/统筹**：总管 E0000（领地：公司公共区）。团队级见 `T00x/workflow.md`，员工级见各 `E00xx/workflow.md`。
> 技能引用一律在 AGENTS.md；本文件只描述多实体协同流程（P7/P8）。

## 1. 需求流入路径（两个入口，机制收敛）

| 入口 | 路径 | 留痕 |
|---|---|---|
| A · 经总管（常态） | 用户 → 总管 demand-clarify 澄清 → PRD 存档 → ticket-split 拆单（父单+子单）→ 分派 | REQ-*.md / 父单正文 |
| B · 用户直派员工 | 用户 → 员工直接执行；值得建单时员工**号池取号**建单（owner 自填 + handoffs 注明"用户直派"） | messages.md 来源备注 + worklog |

两入口汇入同一套文件契约（tasks/ + worklog），总管通过看板被动可见，无第二真相。

## 2. 员工 ↔ 员工（工单交接协议）

- 交接 = 改 `owner` + 追加 `handoffs` 单行 JSON（换人不换状态）；
- 上一手交付物 = 下一手输入物（`inputs` 引用，不复制）；
- 有先后依赖 → 下游单挂 `blocked_by: [上游ID]`，上游全 done 才开工；解锁信号 = 看板黄条/总管巡检通知/自查；
- 同一员工并行多单 → 一会话一单（工位卡隔离，见 concurrent-work）。

## 3. 员工 ↔ 团队

- 员工→团队归属以 roster「团队」列为唯一权威（team.md 不维护名单）；
- 团队负责人（lead）职责：统筹团队 workflow、审定团队级技能、组内派单与互审；成员可提案，lead 定稿；
- 跨团队借调：由双方 lead 协商，总管备案（roster 团队列可多值）。

## 4. 团队 ↔ 团队

- 团队间不直接派活：A 团队需要 B 团队产出 → A 的 lead 向总管提出 → 总管拆单派给 B（保持调度中枢唯一）；
- 跨团队项目：project.md `team` 字段可多值，工单归属项目不归属团队。

## 5. 升级路径（卡住了找谁）

员工卡住（阻塞超期/需求不明/越权请求）→ 报团队 lead → lead 拍板不了或跨团队 → 报总管 → 总管决策不了或需用户拍板 → 上报用户。每级升级在工单 messages.md 追加一条（时间+原因）。

## 6. 需求闭环

拆单时建父单（type: 需求，owner=总管）→ 子单全 done → 父单 review → 用户验收 → done。看板父单详情显示子单进度（🧩 n/m）。

## 7. 例行机制（总管主持）

| 机制 | 频率 | 内容 |
|---|---|---|
| 开工巡检 | 每会话 | 阻塞解锁/看板告警/号池水位/归档提醒/知识库评审（见 AGENTS.md 启动流程） |
| 结构自检 | 结构变更后 | `--check-structure` + 说明书同步 |
| 制度落实 | 用户触发 | 规章制度落实 SOP（dispatch-sop） |
