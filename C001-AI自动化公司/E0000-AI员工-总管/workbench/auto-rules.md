# 派发规则表（auto-rules）

> **定位（诚实声明）**：本表是总管派发时的**决策参考策略表**，不是自动执行机制——
> "自动化"的含义是：总管派发时按本表匹配需求类型，命中即按表执行（免逐单问用户），
> 语义匹配（用户表述含糊时）仍由总管判断。未来 opc_patrol 心跳可消费本表做预分派建议。
> 规则格式：触发条件 → 动作（创建任务 + 派发给谁）。

## 规则列表
- 规则 R1（分析/售前线）
  - 触发：需求类型 = 数据分析 / 研究 / 报告 / 情报整理 / 对比 / 需求分析 / 售前方案 / 竞品 / 标书
  - 动作：创建 TSK 任务，自动派发给 E0001（售前工程师）
  - 例外：涉及跨项目汇总或需总管定夺的，转人工
- 规则 R2（项目线）
  - 触发：需求类型 = 项目管理 / 立项 / 排期 / 进度跟踪 / 资料归档 / 周报
  - 动作：创建 TSK 任务，自动派发给 E0002（项目经理）
- 规则 R3（中枢线）
  - 触发：需求类型 = 员工管理 / 调度 / 公司级协调 / 不确定归属
  - 动作：总管（E0000）自处理或人工判断派发

## 说明
- 规则由总管在派发时判断命中；命中 R1/R2 则免人工中转
- 规则变更需记录日期与原因
- 最后更新：2026-08-29（R1 更名分析/售前线并扩充触发词——E0001 分析员改名售前工程师；此前 2026-08-26 初版）
