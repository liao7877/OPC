# P0004 · 公司看板与工作记录系统

> 三级可视化看板体系（公司驾驶舱 / 团队看板 / 个人工作台）+ 员工自记录机制。
> 需求规格：`REQ-三级可视化看板系统.md`（v2，三轮评审定稿，问答实录见附录 A）。
> 项目归属：P0004 | owner E0000 | team T001（本项目是 T001 团队看板的首个示范项目）。

## 一、怎么用（30 秒上手）

| 页面 | 位置 | 打开方式 |
|---|---|---|
| 🏢 公司驾驶舱 | `../../companies/C001/dashboard.html` | 双击（统计/员工/团队/项目/动态/风险 六模块） |
| 🧩 团队看板 | `T001-AI开发团队/teamboard.html` | 双击（成员/统计/项目/动态/公告/资产） |
| 🧑‍💻 个人工作台 | `E000x-AI员工-岗位/mydesk.html` | 双击（身份/统计/工作记录/我的工单） |
| 🗂 工单协作看板 | `workbench/kanban.html` | 双击（原有，支持深链 `?id=TSKxxx` / `?owner=` / `?participant=`） |

三级页面互链互通；所有数据 ≤3 秒自动同步（文件变动 → 生成器重跑 → 页面轮询刷新）。

## 二、怎么保活（三条防线）

1. **页面自检**：每个看板头部显示"数据生成于 …"；超过陈旧阈值（默认10分钟，可调，三页共享记忆）变黄告警——看到黄条就说明生成器没在跑。
2. **一键保活**：
   - `run_boards.bat`（公司根）—— 顺序重新生成全部数据并拉起双 watcher 常驻；
   - `run_boards.bat once` —— 只生成一次不常驻；
   - `powershell -File register-task.ps1` —— 注册计划任务开机自启（一次性操作）。
3. **会话兜底**：总管每次开工先跑一次 `run_boards.bat once`（已写入 dispatch-sop）。

> 原理：`file://` 下浏览器不能执行本地脚本，页面轮询只能"重拉"数据文件，真正"重新生成"靠 HTML 之外的生成器。所以**改了 worklog/task.md 后若没跑生成器，看板数字不会变**——这是看到黄条的第一排查项。

## 三、数据从哪来（谁维护什么）

```
你/AI 维护的「真相文件」                      生成器自动产出（勿手改）
─────────────────────────                  ─────────────────────────
E0000…/roster.md        ←唯一权威    dashboard-data.js + dashboard.html（公司根）
  （岗位/在职/团队列）                  T001…/teamboard-data.js + teamboard.html
E000x…/workspace/worklog.md          E000x…/mydesk-data.js + mydesk.html
  （个人工作记录，只增不删）
P####…/project.md      ←team 字段     （HTML 模板放 ../../companies/C001/page-templates/，公司根；
T001…/notices.md         决定归属       改模板后跑一次生成器即全员刷新）
workbench/tasks/…/task.md ←工单数据
```

- 生成器（2026-08-28 机制上提 OPC 根）：`opc_tickets.py`（工单）+ `opc_dashboards.py`（三级切片+交叉核验），公司内经 `run_boards` 薄壳调用，均带 `--selftest`。
- **交叉核验（自动告警，出现在公司级"风险"模块和本人 mydesk）**：工单型 worklog 缺 ticket、引用不存在工单、在途工单没记 worklog、worklog 已完成但工单没关单等双账不一致。
- 统计口径：完成率 = 已完成/全部有效条目（累计）；在途 = 计划中+进行中；进行中超 14 天未更新进"停滞预警"。

## 四、员工日常纪律（三段式）

接到任务 → worklog 加一条 `status: 计划中`（工单活必填 `ticket: TSKxxxx`）；开始干 → 改 `进行中`；干完 → 改 `已完成`（有交付物挂 `deliverable:` 路径），同时把对应工单状态关掉。**条目只增不删**（删了历史统计会对不上）。
