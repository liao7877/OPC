# T001 团队开发规范（team-dev-standards）

> **本技能是「团队级」技能**：只承载 T001 团队内部的开发约定，供团队内成员使用。
> 三层技能体系定位：
> - **公司级**（公司根 `skills/`）：全公司共用，如工单系统 `ticket-system` —— 工单操作一律以它为准
> - **团队级**（本目录 `T001-AI开发团队/skills/`）：团队内共用，如本技能 —— 只补团队专属约定
> - **私有**（员工目录 `skills/`）：仅本人
>
> **功能单一原则**：本技能不做工单操作（那是公司级技能的职责），只讲团队开发约定。

## 1. 交付标准（团队成员通用）

- 代码/产物交付前自查：可运行、无破坏性改动、关键逻辑有注释。
- 交付物命名 `YYYY-MM-DD-主题.扩展名`，放入工单的 `deliverables/`。
- 跨人协作改动前，先看工单 `messages.md` 最新状态（文件系统并发无锁，避免覆盖他人工作）。

## 2. 评审约定

- 评审意见以「问题-建议」格式追加到 `messages.md`，不直接改他人交付物。
- 评审通过后由工单当前负责人推进状态，评审人不越权改 `owner`。

## 3. 与公司级技能的分工

| 场景 | 用哪个技能 |
|---|---|
| 建单 / 改状态 / 流转 / 完成 / 输入物 / 告警处理 | **公司级** `../skills/ticket-system/SKILL.md`（从团队目录为 `../../skills/ticket-system/SKILL.md`） |
| 团队内交付规范 / 评审约定 / 命名规则 | **本技能**（团队级） |
| 个人专属流程 | 员工私有 `skills/` |

## 4. 红线

1. 不重复制定公司级已有规范（避免双份真相漂移）。
2. 本技能变更需团队内同步（成员 AGENTS.md 引用的是本文件路径，改动即生效）。
