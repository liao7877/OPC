# AI员工-售前工程师 知识库（员工级）

> **定位**：三级知识库的员工级——**员工级 `knowledge/`（本人可写）** → 团队级 `T00x/knowledge/`（组内可读）→ 公司级 `knowledge/`（全员可读）。
> **维护**：本人独占，可自由增删改（领地自治，留痕 + 可逆）。
> **依据**：MECHANISM_PLAN §十七（决策 #19）；原则见 PRINCIPLES P33。

## 一、与 `memory/` 的分工（最关键的一条）

| | `memory/` | `knowledge/`（本目录） |
|---|---|---|
| 性质 | 时序私人记忆（日志、流水） | 结构化可复用知识（成品） |
| 表达约束 | **细节优先**，不受精简约束（P31 例外） | 精简、本质而非肤浅（P31） |
| 是否进索引 | ❌ 不进 | ✅ 进（索引行 → 摘要 → 全文） |
| 能否上浮 | ❌ 不上浮 | ✅ 可上浮到团队 / 公司级 |

**一句话**：随手写的东西进 `memory/`；提炼后下次还用得上的，进 `knowledge/`。

## 二、组织原则

- **目录 = 主题分类**，成熟度一律看 frontmatter `status` 字段，不靠目录名（P33 ④）。
- **每级同构**：`KB.md`（本文件，人写）+ `glossary.md`（受控词表）+ `INDEX.md`（生成物，勿手改）+ 主题子目录。
- **三级加载**：索引行（常驻）→ `summary`（命中才读）→ 全文（确认有用才读）。**`summary` 必填**——不填则加载机制失效。

## 三、查询顺序

自己 `knowledge/` → 所属团队 `knowledge/` → 公司级 `knowledge/` → 外部（联网/文件系统）。**由近及远，命中即停**——自己有就别往上翻。

## 四、上浮出口

条目的**准入判据**（两条同时成立）：① 脱离本人与原上下文仍成立；② 团队或公司里 ≥2 个同事也用得上。

不满足的**不是「换个方式上浮」，是「不该上浮」**——老实待在本层。满足的向团队 lead（或总管）发起上浮：物理搬家 + 原处留**真实 `.md` 存根**（`status: 已上浮`），作者登记为本人、维护人登记为接手的管理员。

## 五、红线

1. 只对自己有用、纯流水账 → 放 `memory/`，别污染这里；
2. 状态写字段，不建 `草稿/` `已归档/` 之类的目录（P33 ④）；
3. 团队级与公司级知识对本人**只读**——要定制就 COW 复制到本目录并标 `derived_from`，**源不变**；
4. 术语走 `glossary.md` 归一，不造同义词；
5. 永不自动删除自己的条目，过时了改 `status` 归档（P33 ③）。

## 条目模板（登记新条目时复制此骨架填空——frontmatter 是机器可读面，人填完即进索引）

```markdown
---
title: 条目标题（检索命中的关键，写用户会搜的词）
type: method        # method=怎么干 / reference=查什么 / case=案例与解释 / glossary=术语
tags: [标签1, 标签2] # 术语与同义词归一见 glossary.md；禁用词不进 tag
summary: |
  2-3 句摘要：这条知识解决什么问题、何时用、结论是什么——不填则三级加载失效
status: 正式         # 草稿/候选/正式/待复核/已归档/已废弃（状态进字段不进目录名，P33）
author: E000x        # 作者（内容答疑找谁）
maintainer: E000x    # 维护人（格式复核，与 author 分离：解决搬家后无人懂细节）
review_by: 2026-12-31 # 复审到期日（TTL，到期巡检 #14 提醒）
source: ""           # 外部资料的原文指针（登记型条目必填，正文只写结论）
derived_from: ""     # 衍生自上级哪条（COW 变体必填，源不变）
supersedes: ""       # 取代哪条旧条目
---

正文：按 type 定位写——method 写步骤、reference 写事实、case 写背景与结果。
```

> `hits`（命中热度）/ `tokens`（体积估算）由机器维护，人勿填。

## 结构权属（默认冻结，2026-08-30）

- 本层目录结构默认视为**用户设计**：冻结——任何人（含本人/总管）不得增删改名/移动/重分类；需要调整 → escalate 向用户汇报「动什么/为什么/建议」，拍板后执行
- **授权自治登记处**：用户明示「此目录归你自治」→ 在此登记：`<子目录> → 授权 <E000x> 自治（日期）`；无登记 = 冻结
- 内容层不受限：条目登记/提炼/补 frontmatter 自由（按上方条目模板）
